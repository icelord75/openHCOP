# Симуляционные тесты прошивки

Стенд на [simavr](https://github.com/buserror/simavr) запускает прошивку ATtiny44
на 8 МГц, подаёт сигналы CYP1 (PA0) и IGN (PA2), как от трамблёра и ЭБУ,
и проверяет выходы катушек.

## Установка (Debian/Ubuntu)

    sudo apt install gcc-avr avr-libc simavr libsimavr-dev

## Запуск

    cd sim
    make        # собрать прошивку из ../src/main.c и прогнать тесты
    make v      # то же, с выводом каждого переключения выходов

Код возврата 0, если все тесты прошли, 1, если есть ошибки.

## Что проверяется

| Тест | Сценарий |
|------|----------|
| T1 | IGN до первого CYP: катушки молчат, LED мигает раз в 0,5 с |
| T2 | 3000 об/мин: порядок 1-3-4-2, накопление = длительность импульса IGN |
| T3 | CYP держится в нуле на нескольких фронтах IGN: без повторной синхронизации |
| T4 | CYP пропал на 2 цикла: порядок продолжается |
| T5 | Фронт CYP во время накопления: следующей идёт катушка 1-го цилиндра |
| T6 | IGN залип в нуле: аварийное отключение через MAX_DWELL (20 мс), порядок сохраняется |
| T7 | 8000 об/мин: 16 искр без потерь, задержка искры < 15 мкс |
| T8 | 1,2 с без сигналов: сторожевой таймер не перезагружает МК |
| T9 | Ложный импульс CYP в первой четверти цикла: игнорируется |
| T10 | ЭБУ пропустил 2 импульса IGN (отсечка зажиганием): следующий CYP сразу восстанавливает порядок |
| T11 | Ложный импульс CYP в конце цикла принят: одна искра не в тот цилиндр, настоящий CYP восстанавливает порядок |

Стенд моделирует двигатель: события зажигания идут с постоянным периодом,
настоящий импульс CYP приходит перед каждым четвёртым (1-й цилиндр).

## Ограничения

- simavr не учитывает фьюзы и CLKPR, частота задана в стенде (8 МГц).
- При изменении `MAX_DWELL_US` в `src/main.c` поменяйте `MAX_DWELL_MS` в `harness.c`.
- Сигналы идеальные, без дребезга; помеха на CYP моделируется только одиночным импульсом (T9, T11).
